Supplier File Importer — Full Design

BMS Simulator Companion · Assembly Import Feature · 2026-03-31

1 · What we're building

A browser-side importer that reads a supplier's Modbus or BACnet point list (CSV or XLSX), walks the user through a 3-step wizard, and saves a fully-populated Assembly to the Assembly Library. All existing steps (Device Setup, Map Points, Sim Values, Generate) are unchanged — they just gain a richer starting point.

2 · The 3-step import wizard

Step 1

Upload & Detect

  • Drag-drop or browse for .csv or .xlsx
  • SheetJS parses in-browser — no server needed
  • If XLSX has multiple sheets → show sheet selector
  • Auto-detect: Modbus vs BACnet (from column names)
  • Override protocol if wrong
  • Show raw row/column count for confirmation
Step 2

Map Columns

  • List of target fields (Name, Register/Instance, Data Type, Scale, Units, R/W…)
  • Auto-detect pre-fills matches by column name heuristics
  • Click any pill to assign/change that column
  • Optional fields can be skipped → defaults applied
  • Name the assembly before continuing
Step 3

Preview & Save

  • Table of all imported points with mapped values
  • Address base toggle (0 / 1) in table header — flips all address values live
  • Bad rows flagged in red (missing address / name)
  • Optional: filter to R-only or include W points
  • Save → writes to Assembly Library

3 · Address base toggle — how it works

Toggle is on the preview table (Step 3)

  • Column selection (Step 2) is clean — just pick the column
  • In Step 3 header: Address base: [0] [1]
  • Toggle 0: addresses stored exactly as imported
  • Toggle 1: subtract 1 from every address — stored result is 0-based
  • Values update live in the table — you see the numbers change
  • Same toggle applies to BACnet instance numbers

Internal storage is always 0-based

Simulator config + ThingsBoard JSON always receive 0-based addresses.

4 · Data type & field normalization

32-bit types (_HI/_LW pairs) are merged into a single SimPoint consuming 2 registers — the _LW row is skipped.

Formula-based instances (Gree: (N-1)*256+131072) are evaluated with N=1 for the assembly default.

Protocol hintModbus if any register/fc/modbus column found; BACnet if object/instance/bacnet found

When multiple columns match the same field (e.g. both Address_0based and Register_Number_1based), all are shown as pills — the closest match is pre-selected, user clicks to override.

7 · Implementation approach

New files

  • src/components/SupplierImportTab.tsx — the 3-step wizard UI
  • src/lib/supplierImport.ts — parsing, mapping, normalization logic
  • src/lib/columnDetector.ts — auto-detection heuristics

New dependency

  • xlsx (SheetJS) — reads CSV + XLSX in-browser, no server
  • ~500KB gzipped; widely used, actively maintained

Where it lives in the UI

  • New tab in the app nav: "⊕ Supplier Import"
  • Sits alongside (not replacing) the existing 5-step workflow
  • After saving an assembly → app navigates to Device Setup and highlights the new assembly in the library
  • Works for both new projects and adding to existing ones

8 · In scope / out of scope

✓ In scope
  • CSV and XLSX import
  • Multi-sheet XLSX (sheet selector)
  • Modbus + BACnet protocols
  • Auto column detection with manual override
  • Address base 0/1 toggle on preview
  • Data type normalisation (all 5 supplier formats)
  • 32-bit register pair merging (_HI/_LW)
  • DEV / non-simulated object type skipping
  • Save to Assembly Library with source filename
  • Navigate to Device Setup after save
✗ Out of scope (v1)
  • Formula-based BACnet instances (Gree) — N=1 default only
  • Enum value import (Notes / Enum_Values columns)
  • Alarm code reference sheets (Daikin)
  • Editing points during the import wizard
  • Saving column mapping as a reusable template
  • Direct import from URL / cloud storage
